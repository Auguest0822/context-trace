# 言迹 ContextTrace：腾讯云服务器与初赛评测部署方案

> 适用资源：腾讯云服务器 2 核 CPU、2 GB 内存、40 GB 磁盘。这里将“40G 内存”按 40 GB 磁盘理解；若实际配置不同，重新评估资源。

## 一、结论

使用腾讯云服务器作为**团队联调和人工演示环境**。初赛自动评测以仓库中的代码、配置说明、初始化脚本、样例数据和测试命令为准，不能依赖评测系统访问这台服务器。

seekdb 官方 Docker 镜像给出的最低主机要求为 1 核 CPU、2 GB 内存，且说明镜像面向测试用途。因此本机达到最低门槛，但内存余量很小；是否能同时稳定运行 seekdb 和 Python API，必须通过实际监测确认。参考：[seekdb Docker 镜像说明](https://github.com/oceanbase/docker-images/blob/main/seekdb/README.md)。

## 二、三种运行模式

| 模式 | 用途 | 数据库 | 验收要求 |
| --- | --- | --- | --- |
| 本地与自动评测 | 开发、测试、评测系统复现 | 按仓库说明启动的本地 seekdb | 不需要腾讯云 IP、账号或预存数据即可跑通最小 Demo |
| 团队联调 | 三人共享接口和样例数据 | 腾讯云上的 seekdb | 前后端访问同一 API；服务异常不影响本地开发 |
| 人工演示 | 展示完整交互和可视化 | 固定版本与脱敏演示数据 | 视频、截图、报告数字与提交 tag/commit 一致 |

## 三、服务器上放什么

首选只运行 seekdb、轻量 Python API 和少量演示数据。embedding 生成、大批量导入、完整评测和模型推理优先放在开发机或单独算力环境。不要在 2 GB 机器上同时运行多个重服务。

建议先只启动 seekdb，完成建表、插入、关键词检索和向量检索的冒烟测试，再启动 Python API。记录启动后与查询期间的内存、磁盘占用及容器重启情况。若出现 OOM、频繁重启或查询明显不稳定，停止将该服务器作为共享数据库，改为仅保留轻量演示入口；项目的本地运行流程继续保持可用。

## 四、仓库应提供的复现入口

评测环境的具体规则尚需以本届官方提测说明为准。在规则明确前，仓库至少准备：

1. `README.md` 和 `docs/reproduction.md`：写清依赖、启动命令、样例导入、演示与测试命令。
2. `python/yanji/store/schema.sql`：在固定 seekdb 版本上验证过的建表语句。
3. `data/samples/`：脱敏且可重复导入的最小样例。
4. `.env.example`：本地默认值和可选的远程连接参数；不提交真实密码或 API Key。
5. `Makefile`：至少提供安装、初始化、Demo 和测试入口；每个命令都在干净环境实测。
6. `docs/RESULTS.md`：记录执行命令、代码版本、数据集、环境和结果。

建议所有连接信息从环境变量读取，例如 `SEEKDB_HOST`、`SEEKDB_PORT`、`SEEKDB_USER`、`SEEKDB_PASSWORD`、`SEEKDB_DATABASE`。不要在 Python 代码、前端代码或测试数据中写死腾讯云 IP。自动评测若提供自己的数据库配置，应可直接覆盖这些变量。

## 五、网络与数据边界

数据库端口 `2881` 和管理界面端口 `2886` 不直接开放给整个公网。团队成员通过受控网络访问；人工演示对外只开放必要的应用 API。演示数据要脱敏，并准备重新初始化的脚本，避免多次演示后数据状态变化。

## 六、实施与验收顺序

| 阶段 | 操作 | 通过条件 |
| --- | --- | --- |
| 1 | 在开发机完成本地 seekdb + Python 最小闭环 | 不依赖腾讯云服务可写入、检索并返回出处 |
| 2 | 在腾讯云启动 seekdb，导入同一份样例 | 小规模查询稳定，资源占用可接受 |
| 3 | 部署轻量 Python API，前端连接联调 | 写入、检索和控制台显示使用同一份数据 |
| 4 | 在干净环境按 `docs/reproduction.md` 重跑 | 队友不靠口头指导完成 Demo 与测试 |
| 5 | 固定提交版本、数据和演示结果 | 自动评测提交与人工审核材料一致 |

**决策原则：仓库可复现性优先于服务器持续在线。** 腾讯云实例帮助团队协作和展示，但不成为初赛得分的单点依赖。
