# 言迹 ContextTrace：14 天团队开发计划

> 从实际开工日记为 D1，连续执行 14 天。团队成员：队长（Python 引擎、seekdb、接口、评测）、前端 A（控制台）、前端 B（输入解析、Agent Plugin、文档）。

## 两周交付目标

在真实 seekdb 上跑通“带出处的记忆写入 → 混合检索 → 预算选择 → Agent 调用”，并提供接入真实数据的控制台、可复现的评测和 3 分钟演示。浏览器扩展是主线完成后的加分项。

## 每日协作节奏

1. 开工前用 10 分钟同步：昨天完成什么、今天交付什么、当前阻塞是什么。
2. 当天的接口或数据结构变更，由修改者同步给另外两人；前端 mock 数据与真实 API 保持同一格式。
3. 收工前演示当天验收项，把执行命令、环境、结果和未解决问题记入 `docs/RESULTS.md`；把 AI Coding 的使用与人工验证记入 `docs/AI_USAGE.md`。
4. `main` 保持可演示。实验走独立分支；提测使用 tag 或固定 commit。

## 进度落后时的取舍

优先保住 D7 的真实闭环与 D12 的真实评测。控制台先完成时间线、召回回放、冲突档案；成本看板可简化。浏览器扩展、PDF/Git 全量解析、复杂自动冲突判定排在主线之后。

队长在 **D1 定接口、D7 验闭环、D12 锁定评测口径、D13 冻结功能**。每个阶段都以可运行成果验收。
